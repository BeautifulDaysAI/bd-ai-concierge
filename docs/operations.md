## ☀️ 朝のチェック係（毎日 7:00-7:30）

**ローテーション制：4名で週1回ずつ**

### 手順

1. Slack で「☀️ 朝の市況ドラフトが準備できました」通知を確認
2. `/admin/morning-brief` を開く
3. AI が生成したドラフトを確認
4. **チェック項目**：
   - [ ] 数値（株価、為替、指標）の正確性
   - [ ] 出典の妥当性
   - [ ] 「絶対」「必ず」「保証」など断定表現がない
   - [ ] 個別商品名（銘柄、保険名）が含まれていない
   - [ ] 「AI作成・担当者確認済」と末尾に明記されている
   - [ ] BD のトーンに合っている
5. 必要に応じて編集
6. 「承認して配信予約」ボタンをクリック
7. **これで完了！** 7:30 に自動配信される

### NG なら却下

明らかに不適切な内容（誤情報、断定表現、商品推奨）が含まれている場合：
- 該当箇所を削除し、代わりに「（本日の市況サマリは見送りです）」とだけ書いて承認
- 新もとに Slack で報告（プロンプト改善のため）

### チェック時間の目安

慣れれば1回 5〜10分。

## 🚨 Lv.3 案件対応（随時）

### 通知が来たら

Slack で「🚨 個別商品名を含む相談がありました」が届く

### 手順

1. `/admin/messages` を開く
2. 該当会員のメッセージを確認
3. **24時間以内に担当 FP からフォロー連絡**
   - LINE で「ご連絡が遅くなりました」と一声かける
   - 担当 FP との相談予約を提案
4. 必要に応じて、その場で予約調整

Lv.3案件は「商品判断」「契約判断」を含む重要案件です。
**放置しない・AIに任せきりにしない**ことが信頼の基盤になります。

## 💬 FPからお客様への個別メッセージ対応（LINE Official Account Manager）

予約が確定したお客様に、Zoom URLの案内など**FPから直接**LINEメッセージを送りたい場合の手順。
Bot（自動応答）とは別に、LINE Official Account Manager（manager.line.biz）から手動でメッセージが送れる。

### 事前準備：FPのアクセス権限設定（管理者が1回だけ行う）

1. https://manager.line.biz/ にログイン（**管理者権限を持つアカウント**で）
2. 左メニュー「設定」→「権限管理」を開く
3. 「メンバーを追加」をクリック
4. 権限の種類を選択：
   - **運用担当者**（メッセージ作成・チャット返信・分析閲覧が可能。設定変更は不可）を推奨
   - 全権限が必要な場合のみ「管理者」を選ぶ
5. 「URLを発行」をクリックし、発行された認証用URLをFPにメール等で送付
   - **このURLは発行から24時間で失効し、1人しか使えない**（使い回し不可）
6. FPはURLを開き、自分のLINEアカウント（ログイン用メールアドレスの事前設定が必要）で認証すれば完了

### 事前準備：手動チャット機能をONにする（管理者が1回だけ行う）

1. manager.line.biz →「設定」→「応答設定」を開く
2. 「チャット」をONにする
3. **「Webhook」は絶対にOFFにしない**（Botが動かなくなる）

→ この設定で、Bot（Webhook自動応答）とFPの手動チャット返信が**共存**する。

### Botとの競合について（重要・必ず理解しておくこと）

チャットとWebhookを両方ONにすると、お客様からのメッセージは**Webhookサーバー（Bot）とLINE公式アカウントのチャット画面の両方に同時に届く**。これは公式仕様であり、以下の点を必ず把握しておく：

- **FPからお客様へ一方的にメッセージを送る分には、Botとの競合は起きない**（Zoom URL案内など、お客様からの返信を待たない一斉送信・個別送信は無条件で安全）
- **お客様がそのメッセージに返信してきた場合、Bot（自動応答）も同時にその返信を受け取り、通常のロジック（予約フロー・キャンセル判定・AI応答）で自動的に返信してしまう。** FPが手動で返信するタイミングと重なると、お客様に**2通の異なる返信が届く**可能性がある
- 現状、特定のお客様だけBotを一時停止する機能はコード上未実装。必要に応じて別途実装を検討する

### 手順：予約確定済みのお客様に個別メッセージを送る

1. manager.line.biz →「チャット」タブを開く
2. 左側のトーク一覧から該当のお客様を検索（表示名で検索、または`/admin/appointments`で予約情報から会員名を確認してから探す）
3. トーク画面を開き、下部の入力欄からメッセージを直接入力して送信
4. 送信後、**そのお客様から返信が来た場合は、Botの自動応答と自分の手動返信が重複しないか数分待って確認する**
   - Botの自動応答が的外れな場合は、チャット画面から補足のメッセージを送って訂正する
   - 込み入った個別対応が必要になった場合は、以降はチャット中心で対応し、Bot応答は都度上書きするつもりで運用する

## 📅 イベント管理

### 新規イベント登録

Supabase ダッシュボード → Table Editor → `events`：

```
name: 「2026年6月 月例パーティ」
description: 詳細...
starts_at: 2026-06-15 19:00:00+09
location: 「都内 ◯◯ホテル」
capacity: 30
member_priority: true（Memberプラン優先案内するなら）
```

### 出欠の確認

`/admin/events` で各イベントの参加者数を表示。
詳細は Supabase の `event_attendances` テーブルで会員別に確認可能。

## 👤 会員管理

### プラン変更

Free → Member への昇格：

Supabase Table Editor → `members`：
- 該当会員のレコードを編集
- `plan` を `member` に変更
- 保存

### 退会処理

通常は LINE のブロックで自動的に `deleted_at` が記録されます。
手動で退会させたい場合は、`deleted_at` に現在時刻を設定。

30日後に自動削除されます。

漏洩・不正アクセス疑い時：

1. **すぐに**：
   - 該当キーをローテーション
   - Vercel のデプロイ一時停止
2. **24時間以内**：
   - 影響範囲の特定
   - 必要なら個人情報保護委員会への報告検討
3. **1週間以内**：
   - 顧問弁護士と相談
   - 再発防止策の実装
